# 测试指南

本仓库没有自动化测试任务（`gradlew test` 不会执行任何用例）；验证靠编译 + 进游戏手测。

## 编译验证

```powershell
.\gradlew.bat -Dorg.gradle.java.home="C:\Program Files\Java\jdk-17" deploy
```

命令成功即说明 `mod.json`、类名、bundle 路径与 D8 链路都成立；产物内容检查见
[release.md](release.md)。

## 手测清单

进入任意地图（沙盒即可），逐项确认：

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 打开建造菜单并选中一个方块（进入放置预览） | 鼠标周围圆形区域内的单位/子弹/特效按淡入时间渐隐；松开后按淡出时间恢复 |
| 2 | 按住拆除键拖拽区域 | 选区矩形覆盖范围内同样变透明，矩形随拖拽变化 |
| 3 | 按住蓝图选择键拖拽（桌面） | 选区跟随蓝图框，长宽受 `Vars.maxSchematicSize` 限制 |
| 4 | 拖拽重建（rebuild）选择 | 选区透明，且没有长度限制 |
| 5 | 投放物品 / 拖动蓝图时 | 鼠标圆形遮罩生效 |
| 6 | 按住指针透视键（默认 Alt）并移动鼠标，不进行建造/拆除 | 仅指针周围圆形区域变透明；松开后按淡出时间恢复（v1.3） |
| 7 | 打开聊天框/对话框后按住指针透视键 | 不触发效果（键盘焦点守卫） |
| 8 | 在 设置 → 键位 的 build-xray 分类里把指针透视改绑到别的键 | 立即生效且重启后保留；恢复默认回到 Alt |
| 9 | 快速松手结束拖拽/放置 | 遮罩不立刻消失，冻结的选区几何按淡出时间继续显示 |
| 10 | 等离子钻头（plasma bore）工作时镜头经过其光束 | 光束按遮罩范围变透明 |
| 11 | 镜头内有单位/建筑墙体的阴影时触发遮罩 | 阴影同样变透明（v1.3 的 darkness 捕获段），画面其余部分亮度不变 |
| 12 | 设置里把透明度拉到 0% | 完全不变透明（也不会额外渲染） |
| 13 | 设置里调整透明度与半径 | 立即生效，无需重开游戏；数值被记住 |
| 14 | 把淡入/淡出时间拉到 0 ms 与最大值 | 0 ms 立即切换；最大时渐变缓慢，无跳变、无残留 |
| 15 | 关闭「启用」开关 | 效果彻底停止 |
| 16 | 打开聊天框/对话框后再移动鼠标 | 不触发效果（有键盘焦点时不进入蓝图选择分支） |
| 17 | 缩放窗口 / 改变分辨率后再建造 | 遮罩与画面不错位（帧缓冲按当前分辨率重建） |

## 回归关注点

- 单位为 0 或极亮/极暗时效果必须只影响透明度，不改颜色（着色器只乘 alpha）。
- 停止规划后按淡出时间恢复；淡出结束后不应残留半透明剪影，重新开始建造时也不应闪现上一次的
  选区遮罩（`fadeProgress` 归零时冻结几何会被清空）。
- 经过加法混合的内容（光束、发光特效）不能糊掉：`applyTrans()` 的 blit 前必须有
  `Blending.normal.apply()`（上游 v1.1 修复）。
- 低端设备/GLSL 编译失败时：应只禁用效果并打印一条 `BuildXray: ...` 错误日志，
  不影响正常游戏渲染（`ensureShader()` 的降级路径）。
- 指针透视键与蓝图选择键共用 `Core.scene.hasKeyboard()` 守卫：任何输入框获得键盘焦点时
  都不能触发；键位值走 `KeyBind` 自己的 settings 键，不要另存一份。
- `darkness` 窗口只有 `± 0.001`：变透明靠遮罩 alpha，不能把整个黑暗段的 alpha 全减掉
  （否则阴影消失但画面也会一起变亮）。

## Neon 聚合形态

在 Neon 中额外确认：

- `设置 → 模组 → Neon` 的「Build X-Ray」分组里有同样的设置项（主开关 + 透明度 / 半径 /
  淡入 / 淡出四个滑条），且**没有**多出一个「建造透视」独立分类（`bekBundled` 守卫生效）。
- 指针透视键位不在 Neon 设置页里，而是在游戏的 设置 → 键位 的 build-xray 分类下，
  且聚合形态下只注册一次（`BuildXrayMod.init()` 只跑一遍）。
- 关闭该分组的主开关后，分组移入"已关闭的子模组"折叠区。
